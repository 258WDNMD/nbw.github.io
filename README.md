# AI 小说创作台

一个**单文件、纯前端、无需后端**的 AI 长篇小说创作工作台。

双击 `index.html` 就能用。所有数据存在你自己的浏览器里，API 请求由浏览器直接发往模型服务商，不经过任何中间服务器。

---

## 它能做什么

| 环节 | 说明 |
|---|---|
| **一键成书** | 填章数与单章字数，点一次：架构 → 大纲 → 逐章正文 → 摘要 → 定稿，一路跑到底。可暂停、可断点续跑、可关掉网页再来 |
| **架构生成** | 读你填的主题、世界观、人物，产出核心种子 / 角色动力学 / 世界观补全 / 三幕结构 |
| **章节大纲** | 按 N 章生成节奏分布（定位 / 作用 / 悬念 / 伏笔 / 认知颠覆星级） |
| **正文生成** | 流式输出，边写边看；自动注入前文摘要与前情结尾 |
| **AI 改稿** | 在**已有草稿**上增删改：局部修订 / 整章重写 / 增写 / 删改 / 润色 |
| **修订标记** | 红色删除线 = 删去，绿色下划线 = 增添，像 Word 修订模式 |
| **前文摘要** | 分章摘要 + 自动汇总，不漂移；可一键清空并可撤销 |
| **一致性审校** | 检查人物、设定、伏笔、主题是否打架 |
| **写作参考** | 90 条方法论，按 10 个题材分类（通用/科幻/玄幻/奇幻/武侠/言情/悬疑/恐怖/历史/都市），支持同义词搜索，一键复制进「本章额外指导」 |
| **自动匹配参考** | 生成正文、改稿、扩写时，自动从参考库挑出最相关的 1–3 条附进提示词；界面会显示挑了哪几条，可随时关掉 |
| **导出** | TXT（UTF-8 BOM + CRLF，中文不乱码）/ Markdown / JSON 备份 |

**自动保存**：输入后 0.4 秒落盘，切章/切后台/关页强制写盘，15 秒心跳；带上一版备份可回滚。

## 快速开始

1. 下载 `index.html`
2. 用 **Chrome / Edge** 双击打开
3. 左侧「模型配置」→ 选一个预设 → 填 API Key → 「测试连接」→ 「保存配置」
4. 回「仪表盘」填作品名、类型、一句话主题
5. 「AI 生成架构」→「章节大纲」→「AI 写作」

> **不要在内嵌预览窗口里使用**。沙箱 iframe 会禁止网页访问 localStorage，表现为「功能正常但刷新全丢」。工作台会自检并弹红色横幅提示。

### 支持的服务商

DeepSeek、硅基流动、OpenAI 兼容接口、Ollama（本地）、Gemini、OpenRouter 等。

推荐 DeepSeek：便宜、中文好、浏览器直连已实测可用。

## 一键成书

左侧「一键成书」，或者仪表盘顶部那张卡。设好两件事——**几章**、**每章多少字**——剩下的它自己跑：

```
架构（可跳过） → 章节大纲（可跳过） → 第 1 章正文 → 第 1 章摘要 → 定稿
                                    → 第 2 章正文 → 第 2 章摘要 → 定稿
                                    → ……
```

### 两种开始方式

| 模式 | 行为 |
|---|---|
| **重开一本** | 清空章节表，从第 1 章写到你设的章数。开新书用这个 |
| **接着写** | 保留已有章节，从第一个还没写正文的章节往下补。写到一半用这个 |

### 四个开关

- **先生成总架构** —— 已有架构会跳过，不覆盖你手改过的内容
- **先生成章节大纲** —— 「接着写」模式下自动跳过，免得冲掉你手写的标题
- **每章自动写摘要** —— 建议开。下一章靠它接前文，关掉容易写飞
- **每章自动定稿** —— 只是把状态改成「已定稿」，不满意可以关掉自己过一遍

### 中途出事了怎么办

- **暂停**：点「暂停」，当前这一章作废（不留半截稿），已完成的全部保留
- **断网 / 刷新 / 关标签页**：每完成一章就落盘一次。下次打开会看到「从第 N 章继续」
- **报错**：错误原文留在页面上，改完问题（比如换 Key）点「继续」接着跑
- **连接假活**：3 分钟没有任何输出会自动掐断，不会让你干等一夜

### 代价

一个 10 章 × 3000 字的任务大约跑 20–30 分钟，token 消耗不小。页面会在开始前把总量和预估时间算给你看。

> 浏览器本地存储约 5 MB，折合十几万到二十万字。长篇请分几轮跑，并在仪表盘定期「导出备份 (JSON)」。

## 部署到 GitHub Pages

### 需要后端吗？—— 不需要

这不只是判断，是实测结论。用真实 `https://*.github.io` 作为 Origin 发 CORS 预检：

| 服务 | 返回头 | 能否从 Pages 直连 |
|---|---|---|
| DeepSeek | `access-control-allow-origin: https://example.github.io`（回显任意 origin） | ✅ |
| 硅基流动 | `Access-Control-Allow-Origin: *` | ✅ |
| OpenRouter | `Access-Control-Allow-Origin: *` | ✅ |
| OpenAI | 未返回 CORS 头 | ❌ 浏览器会被拦 |

因为请求是**用户自己的浏览器**带着**用户自己的 Key** 发出的，没有中间人，所以不需要代理。

### 什么时候你才真的需要后端

| 你的需求 | 是否要后端 |
|---|---|
| 每个人自己填自己的 Key | ❌ 不用，静态托管即可 |
| 用**你的** Key 给所有访客用 | ✅ 必须。否则 Key 会出现在前端源码/网络面板里，几分钟内被刷爆 |
| 限制用量 / 计费 / 封禁 | ✅ 必须（需要服务端记录） |
| 跨设备同步作品 | ✅ 需要，或用现成 BaaS（Supabase / Firebase） |
| 用户账号体系 | ✅ 需要 |
| 想让作品存在云端、换浏览器也能接着写 | ✅ 需要 |

### 纯静态部署步骤

1. 在 GitHub 新建仓库，例如 `ai-novel-studio`
2. 只把下面四个文件推到仓库根目录：
   ```
   index.html
   README.md
   .nojekyll
   LICENSE
   ```
3. 仓库 **Settings → Pages** → Source 选 `Deploy from a branch` → 分支 `main` / 目录 `/ (root)` → Save
4. 等 1–2 分钟，访问 `https://<你的用户名>.github.io/ai-novel-studio/`

`.nojekyll` 是空的，作用是关掉 Jekyll 处理，避免特殊字符文件被忽略。

### ⚠️ 不要直接推整个项目文件夹

这个仓库里如果还放着你的小说草稿、参考资料、旧版本页面，`git add .` 会把它们**全部公开**。

根目录的 `.gitignore` 已经排除了这些路径。推之前先 `git status` 确认一遍。

## 隐私

- API Key 存在本机浏览器 `localStorage`，**不上传任何第三方**，但也**没有加密**。
- 别在公用电脑上配置。
- 「导出备份 (JSON)」会问你是否包含 Key —— 要分享给别人时选「不包含」。
- 运行日志只记录 Key 指纹（`sk-1a2b…9f8e(len=35)`），不记完整 Key。

## 数据存在哪

浏览器 `localStorage`，键名 `ai_novel_studio_v1`（备份在 `...__prev`）。

- 换浏览器、换设备、清「浏览数据」都会读不到
- 重要节点请导出 JSON 备份，存网盘或 U 盘

## 写作参考怎么自动进场

生成正文、改稿、扩写时，工作台会把**本章标题 + 简述 + 你的额外指导 + 作品类型**拼成检索语，
和参考库比对，挑出最相关的 1–3 条附在提示词里，形如：

```
【写作参考 · 自动匹配（来自你的参考库）】
下面几条与本段任务最相关。请在具体字句里落实它们，不要只是复述原则：
· 时间线是推理的地基——动笔前先画一张精确到小时的时间线表…
· 线索要显眼，但不能刺眼——最好的线索是「第一次出现时读者以为是别的用途」…
```

匹配规则（宁缺毋滥）：

- **中文二字组 + IDF 加权**：罕见词（线索、误会、开篇）权重高，泛词（读者、主角、人物）自动忽略
- **题材硬过滤**：写科幻就只给科幻与通用条目，绝不跨题材塞言情技巧
- **至少 2 个有效词命中**，或 1 个命中且命中词出现在条目标题里
- **匹配不上就不注入** —— 宁可这一章不给参考，也不塞无关的条目
- 写作区会显示「✓ 自动匹配参考」和具体条目名；点条目可复制全文；点按钮可整体关闭

条数默认 3（改稿 2），可在「模型配置 → 写作辅助」调整。
